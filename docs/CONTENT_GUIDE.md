# Content Guide

## Writing Principles

- Write technically.
- Prefer concrete nouns and verbs.
- State what was designed, analysed, tested or measured.
- Avoid self-congratulatory claims.
- Do not write “demonstrates competency”.
- Do not call work “innovative” without evidence.
- Do not call preliminary work “validated” unless validation occurred.
- Distinguish analysis from test evidence.
- Distinguish preliminary design from qualification.
- Distinguish assumptions from measured values.
- State limitations explicitly.
- Use units.
- Use revision and date information.
- Prefer tables where comparison is easier.
- Use captions that explain why a figure matters.
- Never publish numerical claims whose basis has not been checked.

## Examples

Bad:

> This innovative project showcases my strong FEA skills.

Good:

> Six quasi-static load cases were evaluated against the selected structural design criteria.

Bad:

> The structure is fully validated.

Good:

> The preliminary global model satisfies the current static-load criterion; joint-level verification and qualification testing remain outside the present scope.

Bad:

> The new lay-up greatly improves damping.

Good:

> The measured damping metric for each laminate is reported with the specimen count, boundary condition and processing method. Interpretation is limited to the tested configurations.

## Numerical Content

- Give the source or calculation basis for every requirement and result.
- Put units in table headings where practical.
- State safety factors separately from margins of safety.
- Define the margin-of-safety equation and acceptance criterion.
- Do not imply that a model result is test evidence.
- Identify values that are targets, assumptions, measured data or calculated results.

## Figures

- Number figures sequentially within each document.
- Write useful alt text that describes the engineering content.
- Explain in the caption why the figure matters.
- Add a source note when the figure is derived from external or shared material.
- Export technical evidence at a readable resolution without recolouring results for branding.

## Publication Check

Before release, check names, dates, revisions, units, filenames, repository links, permissions, confidential information, technical claims, assumptions, limitations and references.
